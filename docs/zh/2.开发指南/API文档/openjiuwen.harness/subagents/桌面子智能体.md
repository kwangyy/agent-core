# 桌面子智能体（cua_agent）

通过 [cua-driver](https://github.com/trycua/cua/tree/main/libs/cua-driver) 操作本机原生应用的桌面子智能体。

---

## 概述

`cua_agent` 操作真实的应用窗口：列出窗口、读取窗口的无障碍元素树，并发送鼠标、键盘和应用启停操作。
cua-driver 以 stdio MCP 服务器（`cua-driver mcp`）接入，它只是一个轻量代理，所有工具都由交互式桌面
会话中的 `cua-driver serve` 守护进程执行。

网页不归它处理。浏览器自动化由[浏览器子智能体](./浏览器子智能体.md)负责，cua-driver 自带的浏览器工具
不会开放。Discord、Slack、VS Code 等 Electron 桌面应用是普通桌面窗口，由本智能体处理。

用 `create_cua_agent` 创建独立智能体，或用 `build_cua_agent_config` 注册为子智能体，由父智能体通过
`task_tool`（`subagent_type="cua_agent"`）委派。`DeepAgent` 也接受 factory 名 `"desktop_agent"` 作为别名。

**平台**：已在 Windows 上验证。守护进程需要交互式桌面会话，SSH 或无界面会话看不到 GUI。

### 安装与配置

`uv sync --extra cua`（或 `pip install 'openjiuwen[cua]'`）会安装 `cua-driver` 包（0.28.1 及以上），其中自带 driver 可执行文件。从 0.28.1 起，
没有守护进程运行时 MCP 代理会自行启动一个，并在代理退出时将其关闭，无需另外安装或手动启动守护进程。

| 环境变量 | 用途 |
|---|---|
| `CUA_DRIVER_MCP_COMMAND` | driver 命令。默认依次查找：Python 解释器旁的自带可执行文件、`PATH` 中的 `cua-driver`、Windows 安装程序的默认位置 |
| `CUA_DRIVER_MCP_ARGS` | MCP 代理参数。默认 `mcp` |
| `CUA_DRIVER_MCP_TIMEOUT_S` | MCP 请求超时（秒）。默认 `120` |
| `CUA_DRIVER_POLICY_FILE`、`CUA_DRIVER_MANAGED_POLICY_FILE` | 透传给 driver，启用 driver 自身的权限策略，作为智能体权限之下的额外一层 |
| `OPENJIUWEN_SUBAGENT_TASK_TIMEOUT_S` | 单次 `task_tool` 委派的时长上限，对所有子智能体类型生效。默认 `720` |

首次调用模型前，`CuaRuntimeRail` 会检查 driver 能否连到可用的守护进程，不能时报错并给出修复方法。

## function create_cua_agent

```python
def create_cua_agent(
    model: Model,
    *,
    card: Optional[AgentCard] = None,
    system_prompt: Optional[str] = None,
    tools: Optional[List[Tool | ToolCard]] = None,
    mcps: Optional[List[McpServerConfig]] = None,
    subagents: Optional[List[SubAgentConfig | DeepAgent]] = None,
    rails: Optional[List[AgentRail]] = None,
    enable_task_loop: bool = False,
    max_iterations: int = 25,
    workspace: Optional[str | Workspace] = None,
    skills: Optional[List[str]] = None,
    backend: Optional[Any] = None,
    sys_operation: Optional[SysOperation] = None,
    language: Optional[str] = None,
    prompt_mode: Optional[str] = None,
    cua_capabilities: Optional[List[str]] = None,
    cua_instance_key: str = "",
    cua_delivery_mode: Optional[Literal["background", "foreground"]] = None,
    cua_screenshot_multimodal: bool = False,
    cua_snapshot_keep_last_k: int = 3,
    cua_pause_on_user_input: bool = False,
    **config_kwargs: Any,
) -> DeepAgent
```

创建桌面子智能体。cua-driver MCP 服务器和[内置 Rails](#内置-rails) 追加在调用方传入的 `mcps` 和 `rails` 之后。

**参数**:

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `model` | `Model` | *(必填)* | 模型实例。多模态模式需要支持视觉的模型 |
| `card` | `Optional[AgentCard]` | `None` | 智能体身份卡。为 None 时创建 `name="cua_agent"` 的默认卡 |
| `system_prompt` | `Optional[str]` | `None` | 替换默认提示词。为 None 时按[感知模式](#感知模式)选择默认提示词。设置了 `cua_delivery_mode` 时仍会追加[投递模式](#投递模式)说明 |
| `max_iterations` | `int` | `25` | 最大迭代次数。每次元素操作前都要重新快照，低于约 20 时任务容易中途耗尽 |
| `language` | `Optional[str]` | `None` | `"cn"` 或 `"en"` |
| `cua_capabilities` | `Optional[List[str]]` | `None` | 授予的 capability，见 [Capability](#capability)。为 None 时授予 `input` 和 `app_lifecycle`；`core` 总是包含 |
| `cua_instance_key` | `str` | `""` | 隔离 MCP 注册。相同 key（或都为空）的智能体共享同一个 driver 服务器注册 |
| `cua_delivery_mode` | `Optional[Literal["background", "foreground"]]` | `None` | 为所有输入操作固定投递模式。为 None 时由模型逐次选择 |
| `cua_screenshot_multimodal` | `bool` | `False` | 将截图作为图像放入上下文 |
| `cua_snapshot_keep_last_k` | `int` | `3` | 上下文中保留的最近快照数（多模态模式下也是截图数），至少为 1。单窗口任务可设为 `1` 以节省上下文 |
| `cua_pause_on_user_input` | `bool` | `False` | 用户正在使用鼠标或键盘时暂缓桌面操作。仅 Windows 可用 |
| `**config_kwargs` | `Any` | — | 转发到 `create_deep_agent()`，例如 `permissions`、`permission_host` |

其余参数（`tools`、`mcps`、`subagents`、`rails`、`enable_task_loop`、`workspace`、`skills`、`backend`、
`sys_operation`、`prompt_mode`）原样传给 `create_deep_agent()`。

**返回值**: `DeepAgent` — 已配置的桌面子智能体。

**异常**: 以下情况抛 `ValueError`：未知的 capability 名称；`cua_delivery_mode` 不是 `"background"`、
`"foreground"` 或 `None`；`cua_snapshot_keep_last_k` 小于 1。

**示例**:

```python
from openjiuwen.core.runner import Runner
from openjiuwen.harness.subagents import create_cua_agent

agent = create_cua_agent(model, language="cn", cua_capabilities=[])  # 只读：仅 core

await Runner.start()
try:
    result = await Runner.run_agent(
        agent,
        {"query": "列出当前打开的应用窗口。", "conversation_id": "cua-demo"},
    )
finally:
    await Runner.stop()
```

## function build_cua_agent_config

```python
def build_cua_agent_config(
    model: Model,
    *,
    card: Optional[AgentCard] = None,
    system_prompt: Optional[str] = None,
    tools: Optional[List[Tool | ToolCard]] = None,
    mcps: Optional[List[McpServerConfig]] = None,
    rails: Optional[List[AgentRail]] = None,
    enable_task_loop: bool = False,
    max_iterations: int = 25,
    workspace: Optional[str | Workspace] = None,
    skills: Optional[List[str]] = None,
    backend: Optional[Any] = None,
    sys_operation: Optional[SysOperation] = None,
    language: Optional[str] = None,
    prompt_mode: Optional[str] = None,
    cua_capabilities: Optional[List[str]] = None,
    cua_instance_key: str = "",
    cua_delivery_mode: Optional[Literal["background", "foreground"]] = None,
    cua_screenshot_multimodal: bool = False,
    cua_snapshot_keep_last_k: int = 3,
    cua_pause_on_user_input: bool = False,
    permissions: Optional[dict] = None,
    permission_host: Optional[Any] = None,
) -> SubAgentConfig
```

生成 `SubAgentConfig`，父智能体首次委派时用 `create_cua_agent` 实例化。参数在此时即校验，
`ValueError` 情形与 `create_cua_agent` 相同。

**参数**: 与 `create_cua_agent` 相同（不含 `subagents` 和 `**config_kwargs`），另有：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `permissions` | `Optional[dict]` | `None` | 子智能体的权限策略 |
| `permission_host` | `Optional[ToolPermissionHost]` | `None` | 应答权限确认的宿主，见[权限](#权限) |

**返回值**: `SubAgentConfig` — `factory_name="cua_agent"` 的子智能体配置。

**示例**:

```python
from openjiuwen.harness.factory import create_deep_agent
from openjiuwen.harness.subagents import build_browser_agent_config, build_cua_agent_config

coordinator = create_deep_agent(
    model=model,
    subagents=[
        build_cua_agent_config(model, language="cn"),
        build_browser_agent_config(model, language="cn"),
    ],
)
```

## Capability

`cua_capabilities` 从固定目录（`openjiuwen.harness.tools.cua`）中选择 driver 工具。选择结果是 driver
MCP 服务器上唯一的工具白名单；driver 新增的工具在加入目录前不会开放。

| capability | 工具 | 默认授予 |
|---|---|---|
| `core` | `list_apps`、`list_windows`、`get_window_state`、`get_accessibility_tree`、`get_desktop_state`、`get_screen_size`、`get_cursor_position`、`get_session_state`、`start_session`、`end_session`、`check_permissions`、`health_report`、`zoom` | 总是 |
| `input` | `click`、`double_click`、`right_click`、`drag`、`type_text`、`press_key`、`hotkey`、`scroll`、`set_value` | 是 |
| `app_lifecycle` | `launch_app`、`bring_to_front` | 是 |
| `app_termination` | `kill_app` | 否 |
| `recording` | `start_recording`、`stop_recording`、`get_recording_state`、`replay_trajectory` | 否 |

传 `[]` 得到只读智能体（仅 core）。

### function resolve_cua_capabilities

```python
def resolve_cua_capabilities(
    requested_names: Iterable[str] | None,
    available_capabilities: Iterable[CuaCapability] = DEFAULT_CUA_CAPABILITIES,
) -> ResolvedCuaCapabilities
```

把 capability 名展开为工具白名单。总是加入 `core`，去除重复；未知名称记入 `rejected_names`，
不抛异常。`rejected_names` 非空时，两个工厂函数抛 `ValueError`。

**返回值**: `ResolvedCuaCapabilities` — 冻结 dataclass，字段为 `requested_names`、`selected_names`、
`rejected_names`、`allowed_tool_names`。

## 感知模式

智能体用 `get_window_state(pid, window_id)` 观察窗口，返回一次快照：元素树，以及按需返回的截图。
操作优先使用 `element_index` 寻址：可作用于后台窗口，且不移动用户光标。`element_index` 只对该窗口
最新一次快照有效，因此每次元素操作前都要重新快照。

| | 文本模式（默认） | 多模态模式 |
|---|---|---|
| 开关 | `cua_screenshot_multimodal=False` | `cua_screenshot_multimodal=True` |
| 模型 | 任意 | 需支持视觉 |
| 截图 | 以文本占位符进入上下文，提示词告知模型永远收不到截图 | 按需作为图像附加；过大的图像缩成 JPEG，并附缩放系数说明 |
| 像素坐标 | 只从元素 frame 推算 | 从最新截图上读取 |
| 窗口没有可用元素树时 | 汇报该窗口需要具备视觉能力的智能体 | 可以依据截图操作 |

窗口坐标和屏幕尺寸来自 driver 的 MCP `structuredContent`，本智能体总是将其放进工具结果。

## 投递模式

cua-driver 的输入操作带 `delivery_mode` 参数。`background` 在不前置窗口、不抢焦点的情况下投递输入；
`foreground` 会短暂把窗口切到前台。默认由模型保持 `background`，只有后台尝试确认失败后才把单个操作
升级为 `foreground`；部分应用（UWP/WinUI，以及部分 Chromium、Java、Qt 界面）需要这样做。

设置 `cua_delivery_mode` 可改由运维方决定：

- `"background"`：所有输入操作都后台投递。显式的 `foreground` 请求在到达 driver 前被拒绝，智能体改为汇报该限制。
- `"foreground"`：所有输入操作都前台投递，焦点变化是预期行为。

两种情况都会在系统提示词末尾追加对应说明。

## 内置 Rails

`create_cua_agent` 在调用方 rails 之后追加以下 rails：

| Rail | 条件 | 作用 |
|---|---|---|
| `CuaRuntimeRail` | 总是 | 检查 driver 与守护进程，按 capability 白名单注册 MCP 服务器，每次运行开启一个 driver 会话 |
| `CuaElementAddressingRail` | 总是 | 调用同时带 `element_index` 和 `x`/`y` 时去掉 `x`/`y`；driver 会拒绝同时使用两者的调用 |
| `CuaRepeatFailureRail` | 总是 | 同一调用反复得到相同的非成功响应时，第 3 次附加建议，第 6 次拒绝发送 |
| `CuaSnapshotFreshnessRail` | 总是 | 对某窗口操作后的第一次快照去掉 `query`，避免验证被过滤 |
| `CuaProgressRail` | 总是 | 窗口第 3 次回到同一状态时建议换方法，并汇报本次运行进度（见下文） |
| `CuaDeliveryModeRail` | 设置了 `cua_delivery_mode` | 强制固定的投递模式 |
| `CuaUserTakeoverRail` | `cua_pause_on_user_input=True` | 用户活动期间暂缓操作，空闲 5 秒后继续，60 秒后停止并汇报 |
| `CuaScreenshotDownscaleRail` | 多模态模式 | 缩小过大的截图 |
| [`MultimodalContextSummarizerRail`](../rails/rails.md) | 多模态模式 | 只保留最近 `cua_snapshot_keep_last_k` 张截图 |
| `ContextProcessorRail` | `rails` 中未传 `ContextProcessorRail` | 只保留最近 `cua_snapshot_keep_last_k` 个快照结果；更早的结果卸载到工作区，替换为简短预览 |

## 委派结果与续跑

父智能体通过 `task_tool` 委派时，`cua_agent` 的结果 `data` 包含：

| 字段 | 含义 |
|---|---|
| `output` | 子智能体的回答 |
| `resume_task_id` | 回传它可继续同一个桌面会话 |
| `cua_result` | `CuaProgressRail` 的进度报告 |
| `retryable` | `cua_result.status` 不是 `"completed"` 时为 `True` |
| `resume_context` | `status`、`blockers`、`current_window`、`recommended_recovery`、`resume_count` |

`cua_result.status` 为 `"completed"`、`"partial"`（有操作失败）或 `"blocked"`（重复失败的调用被拒绝，
或窗口反复回到同一状态）。这是启发式判断，不代表任务确实完成。`blockers` 最多列出 5 个失败操作，
格式为 `工具名: 错误首行`。

**超时**：`cua_agent` 委派在 `task_tool` 上限前 20 秒自行停止，返回成功结果：`status="timeout"`、
`retryable=True`、`resume_context.last_action_confirmed=False`。桌面会话和已完成的步骤会保留，
但截止时正在执行的操作可能已生效却未被记录。

**续跑**：再次调用 `task_tool`，传 `subagent_type="cua_agent"`、同一个 `resume_task_id`，`task_description`
只写尚未完成的部分。子智能体会收到上次的状态、窗口、blockers 和恢复提示，并被要求先重新快照再操作。
不传 `resume_task_id` 时，每次委派都开启新会话。

## 权限

启用权限引擎后，变更型桌面工具归入 `os_control` 类别，并适用以下内置规则：

| 规则 | 工具 | 决策 |
|---|---|---|
| `cua_desktop_force_terminate_app` | `kill_app` | 拒绝 |
| `cua_desktop_launch_app` | `launch_app` | 询问 |
| `cua_desktop_type_text` | `type_text` | 询问 |

规则使用模型可见的工具名，例如 `mcp_cua-driver_launch_app`。`os_control` 规则的 `pattern: "*"` 匹配该工具的
所有调用；其他 pattern（精确、glob 或 `re:`）匹配调用参数 `text`、`name`、`bundle_id`、`value`、`key`
或 `keys`。以非空 `cua_instance_key` 创建的智能体工具名为 `mcp_cua-driver-<key>_<tool>`，同样受这些内置规则约束。

`kill_app` 被内置规则拒绝，因此默认不授予。请求 `app_termination` 才会授予它，此时系统提示词会追加“先协作式关闭应用”的指引。

在 `task_tool` 委派内部，询问决策无法经父对话到达用户。请传入 `permission_host`，由其
`request_permission_confirmation` 在进程内应答；或只使用允许和拒绝规则。

```python
permissions = {
    "enabled": True,
    "schema": "tiered_policy",
    "defaults": {"*": "allow"},
    "rules": [
        {
            "id": "deny_shell_launch",
            "tools": ["mcp_cua-driver_launch_app"],
            "match_type": "os_control",
            "pattern": "re:(?i)^(powershell|pwsh|cmd)(\\.exe)?$",
            "action": "deny",
            "severity": "CRITICAL",
        }
    ],
}
```

每条规则都应显式写 `action`。只写 `severity` 永远不会产生拒绝。
